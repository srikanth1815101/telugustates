# World editor

A local visual editor for the Telugu States 3D world. It runs on your machine, shows the real
3D world next to a panel of fields, and writes your edits straight into
`Hugo-Project/content`. No Hugo, no build step, no dependencies to install.

```bash
git clone <this repo>
cd telugustates
node admin.mjs        # or: npm --prefix admin start
```

Open <http://localhost:4173>. That's it.

> **Node 20 or newer.** The editor uses only the Node standard library.

---

## What you get

| | |
|---|---|
| **Everything in one list** | House, every tree/plant/crop/animal species, all 61 districts, trails, landmarks, villages, public works, and the calendar. |
| **Search** | Press `/` and type. Search matches names, districts, species and kinds. |
| **Live 3D** | The right pane boots the **real engine** — the same `world.js` the site ships. Click a house and the camera flies there. |
| **Pick with your eyes** | Colours come with a logo-derived palette plus a free picker, so edits stay on-brand. |
| **Surgical writes** | Changing one colour rewrites one line. Unchanged fields are never touched. |

## What you can change

**A house** — name, archetype, facing, width/depth/height, wall colour, roof colour, signwood
colour, props (shade tree, banana clump, kitchen garden, cattle shed, tulsi pot, swing, cart,
hay stack, and so on), weathering, and path width.

**A species** — form, height, spread, branch count, foliage colour and accent colour. This is
where "make the neem darker" lives. It changes every neem in the world at once, because they
are one entry in `content/world/ecology.md`.

**A trail** — title, surface, width, goal, and its start and end coordinates.

**A place** — title, kind, grid cell, note.

**A district** — title, name, Telugu name, state, and capacity.

**The calendar** — simulated hours per day, real days per year, the weather roll interval, and
the seed.

## What is deliberately *not* editable

The editor will not let you break the world:

- **Village squares, lanes and home pins** come from `data/settlements.json`, which
  `tools/settle.mjs` lays out so that nothing collides. Change a district's capacity here, then
  re-run the settler.
- **Acre pools** in each district file are generated by the planner. The editor reads them and
  leaves them alone.
- **A house's exact position** is a pin, not a free coordinate. Move a house by moving its pin.
- **Public works** (poles, spans) are shown read-only; they are funded infrastructure.

If you need to change any of those, the tools in `Hugo-Project/tools/` are the right door.

## How it works

Three parts, all local:

```
browser  ──►  admin/server.mjs  ──►  Hugo-Project/content/*.md
                   │
                   └──►  /preview/js/world.js   (the real engine, unmodified)
```

**The content layer** (`lib/content.mjs`, `lib/yaml.mjs`) reads Hugo front matter and Markdown
bodies. A document is only rewritten when a value actually changed, and only the affected keys
are re-emitted, in their original order. Bodies, comments and key order survive.

**The patcher** (`lib/patch.mjs`) goes further: it keeps the original line structure and
rewrites only lines whose scalar values moved, preserving indentation, quoting style and
trailing comments. This is why a colour edit is a one-line diff rather than a reformatted file.

**The catalog builder** (`lib/catalog.mjs`) does in Node what
`layouts/partials/catalog.html` does in Hugo. The 3D engine loads `catalog.json`, never the
Markdown. Without this file the preview could show a different world than the site ships, so
the builder reproduces Hugo's output — including `hash.FNV32a`, the seed that decides each
house's proportions and details.

### Nothing in the site changes

The editor does not patch, fork or wrap the engine. `Hugo-Project/static/js/*` is served over
`/preview/` byte-for-byte as it ships. Only the two files Hugo normally generates are
synthesised, per request, in memory:

- `/preview/catalog.json` → built from content
- `/preview/app-version.json` → a stub so the update checker stays quiet

So the Hugo site, the Android build and the Netlify deploy are all unaffected. Nothing was
changed in `Hugo-Project` to make this work.

## Checks

```bash
node admin/self-test.mjs      # 27 checks
```

The self-test proves the properties that matter:

- an unchanged save **writes nothing at all**
- a colour change is **exactly one line**
- after a change is reverted, the file is **byte-identical** to before
- bad input (invalid colour, unknown facing, unknown prop, wrong list length) is **refused, not
  written**
- path traversal outside the content folder is refused
- the generated catalog contains what the engine needs (cells, colours, seeds, both languages)

## Layout

```
admin.mjs               `node admin.mjs` from the repo root
admin/
  server.mjs            HTTP server: /api, /preview, and the UI
  self-test.mjs         the checks above
  lib/
    yaml.mjs            small YAML subset parser (not an emitter — see patch.mjs)
    patch.mjs           surgical line-level editing
    content.mjs         read/write documents, preserve front matter
    world.mjs           the map from "thing you see" to "file that holds it"
    catalog.mjs         catalog.json built in Node, as Hugo would
    api.mjs             validated routes
  public/
    index.html          editor shell
    preview.html        boots the real engine
    ui/editor.js        panels, fields, search
    css/editor.css      styles, in the site's palette
```

## Troubleshooting

**The 3D pane says it could not start.** The editor still works — fields and saving are
independent of the renderer. The usual cause is a headless/remote machine without WebGL. The
message under the pane shows the underlying error.

**Port 4173 is busy.** `node admin.mjs 8080`, or `PORT=8080 node admin.mjs`.

**I want the preview to show my edits.** Save, then press **↻ Preview**. The preview reads the
content tree fresh each request, so a reload is enough — there is no cache to clear.

**Something looks wrong in the world.** Run `node admin/self-test.mjs`, then
`git diff Hugo-Project/content` to see exactly what changed. Every edit is a plain text diff.

# Counting published virtual plots

These counts describe records in this offline edition, not followers, comments, registrations on another service, or land titles. The official 60001 APK remains the earlier, separately signed field-test build; this change is a development revision.

`config/record-cohorts.json` contains an explicit roster of the 300 original demonstration usernames. It is not a regular expression: a new username that looks similar does not automatically become a demo. The second roster, `community`, is for deliberately reviewed, approved public records only; keep private evidence/identifiers off the public site. No entry is added by scraping, inferring a follow, or observing a click. A new, unclassified plot stays `unreviewed`. A retired demo's permanently reserved cell does not count as a live plot. Remove a community listing from its roster when removing its public record. Changing a label never edits a reservation, geometry or district.

Preparation emits `atlas.json → recordStats` with totals, per-district counts and labels for **currently published** handles. The previous `total`, district `count`, mapping and directory formats still mean all published records. The local catalog presently shows **300 demos, 0 published community plots, 0 unreviewed plots in 61 districts**. Zero here says nothing about the real social account. The home summary, district tooltip, resident directory/filter, resident action sheet and permalink records distinguish these classes. English and Telugu are supported. The static house page now describes the generated house and entrance instead of saying no house was built.

Reproduce: `python -S scripts/prepare_site.py --write-back`, then `python -S scripts/prepare_site.py --check`, `python -m pytest -q tests/test_record_cohorts.py`, and `npx playwright test browser/record-counts.spec.js`. Re-prepare generates only the public content; do not rerun the one-time migration or reseed existing plots.

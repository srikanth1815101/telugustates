# A metre-scale village, not a map of real roads

**1 model unit = 1 metre.** One projected plot is 63.615 × 63.615 m (4,046.868 m²). Land heights use 1.2× display relief; measured source elevations on records do not. House sizes, a roughly 1.7 m player, path widths and walking speeds are not vertically exaggerated.

## Which plots get homes?

The published SW-origin equal-area grid does not change. Whole rows whose global y is divisible by 3 are reserved for streets. Whole columns whose x is divisible by 12 are reserved for connectors. None of these acres can ever be assigned to a house. **A reserved acre is mostly verge**; the track itself is only 3.75–4.70 m in these demos, within the allowed 3.5–5 m range.

Inside each district, let a road cell through only on land, with no mapped lake, river or mine and slope ≤12°. Start at the safe road cell nearest the original district centre (tie smaller y, then x). Take its four-neighbour connected component. A plot must still pass the original district-edge, water, mining, land-cover and ≤20° slope checks, and must now share an edge with this component. No bridges or real road data are used. Capacity does not include land accessible only from another component.

In the one-time, owner-approved migration, frontage-first replaced straight-line-first. Starting at the root of a fixed breadth-first spanning tree, use the plot requiring **the fewest additional road cells**. Next prefer a frontage with more free legal plots; then distance to the original district centre, plot y/x, and frontage y/x. Neighbour expansion order is S, W, E, N. The tree itself is independent of demand. New residents are sorted by date, then username, **only among the new arrivals**. Replaying locked ordinals verifies the same prefix and never moves an older or retired reservation. The decision and the reason a pure distance sort cannot pass are [recorded here](../debug/village_preflight/decision-brief.html).

## Ordinary rebuild

`python scripts/prepare_site.py --write-back` needs no internet, GIS packages or manual road edits. Checked masks in `data/frozen/village/` store the entire reachable road component and eligible plot bitmap. Each district file is one gzip member: `VIL1`, little-endian int32 `origin_x, origin_y, rows, cols`, then two row-major low-bit-first planes (reachable road, eligible plot). `network.json` records roots, capacities, cutoffs, file hashes and the terrain manifest hash. `config/project.json:village_layout` pins that index and states the rule. SciPy/NumPy are needed only to rebake those masks offline with `scripts/bake_village_network.py`.

For each active house, walk its frontage back to the root and keep only the union. Removed houses disappear from the published roads and pins; their locked ordinal/acre stays retired. Each `site/static/data/roads/<district-id>.json` has cells, parent edges, sampled projected-grid XY curves, `[latitude, longitude]` polylines and widths. Junctions stay inside the reserved intersections. `access_joins` records a point on an actual sampled centreline inside each home’s frontage cell, including road bends. The gate crosses that one public verge to the join; it never guesses where the asphalt would be. Private door paths (1.2–1.8 m) end at the plot boundary; the narrower access across the public verge belongs to the road. Camber, wheel ruts, earth, grass, gravel and the wetness response are stylized. On the 2D map the road lines appear only at neighbourhood zoom.

The budget counts **every** drawn cell, including connectors and the root, independently of how narrow the track looks. Target ≤0.7 per home, hard limit ≤1.0 per district and overall. A capacity or hard-budget error names the affected district/users; do not hand-edit the lock or quietly skip connector cells. If an addition/removal exposes new constraints, review them before publishing. The [61-district CSV](../debug/village_preflight/frontage-first/districts.csv) is the migration snapshot, not a permanently updated count.

**This edition supersedes the old road appearance.** Reservation cells remain for stable addresses, but the world renders narrow earthen paths and short gate approaches. It only generates a village branch when a reviewed home needs it. Natural exploration trails use a separate terrain-cost graph. Lighting covers only the nearby stretches selected by a reviewed and paid site (not an entire district). An optional `?dev=1&lighting=1#/u/demo_user1` review compares one selected test corridor with its ordinary unlit fixture; it is not an entry in the public ledger. Four corner stones identify each occupied acre; no perimeter around every empty acre.
